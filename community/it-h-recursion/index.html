🧭 为什么学递归与分治？

ALGORITHM STUDIO
✅ AND · 你已经会

用循环从 1 加到 n，用函数封装重复逻辑——顺序、分支、循环三种结构你都写过。

⚠️ BUT · 但遇到

树形结构、汉诺塔、归并排序这类"问题里套着同类小问题"的场景，循环写法会变得极其别扭——脑子里同时要装下"现在这一层"和"下一层"。

🎯 THEREFORE · 所以我们需要

一种新的表达：递归——让函数调用一个"更小的自己"；以及一种算法范式：分治——拆开、解决、合并。学会识别递归三要素、追踪调用栈、调试无限递归。

1 道小题，看看你对递归的直觉。真正的判断标准是：问题结构是否天然递归，以及实现成本是否可接受。

core_concept.py

思路：一个列表的最大值，可以看成"第一个元素"和"剩余列表最大值"的较大者。

def max_rec(a): if len(a) == 1: return a[0] rest = max_rec(a[1:]) return max(a[0], rest)

知识精讲

递归与分治：自己调用自己解决问题

递归是函数直接或间接调用自身。正确递归通常具备：明确的递归边界（基准情形）、问题规模逐步缩小、向基准情形收敛。分治把大问题分解为相似子问题，分别解决后合并结果（如归并排序、二分思想）。递归调用借助系统调用栈保存现场；过深递归可能导致栈溢出，可用迭代或尾递归优化思路理解。

方法与范例

方法：先写边界，再写递推式

设计递归：①定义函数含义；②写出最小规模直接答案；③假设子问题已解决，写出如何合并。用小例子手推调用展开与返回过程，确认不会无限递归。

范例：阶乘：n!=n×(n-1)!，边界 0!=1；斐波那契也可用递归，但朴素写法存在大量重复计算，需注意效率。

常见误区：常见误区是缺少边界条件，或子问题规模没有真正变小；另一误区是把所有问题都硬套递归，不顾重复计算与栈深度。

判断原则

如果问题像树一样分叉、像俄罗斯套娃一样嵌套，递归通常清晰。如果只是从 1 加到 n，循环可能更直接。高中阶段更重要的是能读懂递归过程，而不是盲目追求"递归写法"。

📖 模块 3：分治三步——拆开，解决，合并

DIVIDE

把原问题拆成规模更小、结构相同或相近的子问题。

CONQUER

对子问题继续求解；小到基本情况时直接给答案。

COMBINE

把子问题答案合并成原问题答案。归并排序的关键就在这里。

递归强调"自我调用"；分治强调"拆分与合并"。两者经常一起出现，但不是同一个概念。

binary_search · 每次砍掉一半

complexity_intuition · 为什么"每次一半"很快？

线性查找

n → n-1 → n-2 → ...

最坏可能看 n 次。

二分查找

n → n/2 → n/4 → n/8 ...

规模每次减半，约 log₂ n 层。

归并排序

拆分 log n 层，每层合并 n 个元素

总量约 n log n。

📌 一句话收束

递归把问题写成"我先相信一个更小的自己"；分治把问题组织成"拆开解决，再合并答案"。

  • 写递归先写出口：没有出口，所有优雅都会变成爆栈
  • 看递归画调用栈：每一层都要知道自己在等什么
  • 看分治问怎么合并：能拆不算会，能合才是算法

⚠️ 易错提醒

检查递归出口时，总问自己：所有合法输入最终都能走到这里吗？缺少基本情况、规模不收缩、重复计算，是递归程序爆栈或超时的三大元凶。
