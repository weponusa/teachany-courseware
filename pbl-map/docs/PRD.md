# PBL Map — 产品需求说明（PRD）

**版本** 0.2 · **日期** 2026-07-05  
**定位** K12 项目式学习**策划层**：排项目、审覆盖、补缺口、证实施。

**产品北星（目标态）**：逐渐撤分科课，以 **每学期多个高强度 PBL（覆盖包）** 保证 **每个学生** 完成本学期全部课标节点；详见 [`MULTI-PBL-FULL-COVERAGE.md`](MULTI-PBL-FULL-COVERAGE.md)。

**当前 v0.1 实现**：每学期 1 跨学科项目 + 个人路径 + 分科补 gap —— **过渡方案**，与北星兼容的演进路径见该文档 Phase A→D。

---

## 1. 问题陈述

- CN 小初高约 **1189** 课标节点，单次 PBL 核心嵌入 **8–12** 点 → 必须**多项目序列**才能系统覆盖。
- TeachAny PBL 擅长「项目 → 课标」，缺「课标全集 → 反推项目」与**可审计覆盖矩阵**。
- 课堂需兼顾：**教师定方向**与**学生自提问、路径个性化**。

## 2. 目标用户

| 用户 | 需求 |
|------|------|
| 教研员 | 校本/区域 PBL 方案、覆盖热力图 |
| 年级组长 | 学期主题壳、跨学科项目排期 |
| 任课教师 | 课标缺口 → 项目建议 → TeachAny 拆解 |
| 学生 | 主题壳下自提驱动问、个性化路径 |
| 管理者 | 覆盖快照、班级差异度报告 |

## 3. 核心功能

### 3.1 三种模式

1. **项目驱动** — 自由拆解（TeachAny `pbl.html`）
2. **课标驱动** — 未覆盖节点 → 跨学科项目草案建议
3. **地图驱动** — 学段×学科覆盖矩阵

### 3.2 策划包（Plan Package）

**目标态：一个学期 = 一个覆盖包（Semester Coverage Pack）= K 个 PBL**，节点划分后并集 = 本学期课标池；**每个学生须完成包内全部 K 个项目**，个人台账 gap=0 方可过关。

**过渡态（v0.1）**：一个学期 = 1 个跨学科 PBL + 分科补 gap —— 见 G3/G5 样例。

目标态要点：

- `mandatoryNodeIds` / `certifiedNodeIds`：每项目必达节点（划分，不交叠）
- 驱动问可个性化，**mandatory 清单不变**
- 两级掌握：M（项目产出）+ C（包内 micro-block + 短测）
- 个人 `studentCoverageLedger`，非仅班级并集审计

**样例**：`data/plans/g3-our-campus.json`（过渡）· `docs/MULTI-PBL-FULL-COVERAGE.md`（目标态）

### 3.3 学生自主

- 双栏：教师主题壳 / 学生驱动问 + 产出意向
- 班级路径差异度（Jaccard）

### 3.4 覆盖审计

- 绿/黄/红矩阵；数据源：`pbl_runs` + 预期矩阵对比

## 4. 非目标（v0.1）

- 音体美课标树
- 服务端多校账号（Phase 3）
- 全自动生成 100+ 项目（需教研把关）

## 5. 成功指标（试点）

| 指标 | 目标 |
|------|------|
| 策划包覆盖率达预期 | G3 样例 ≥ 65% 核心节点有预期标注 |
| 班级差异度 | 同主题 ≥ 0.4 |
| Map → TeachAny 转化 | 跳转拆解完成率 ≥ 60% |
